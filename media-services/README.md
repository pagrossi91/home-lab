# Media Stack - Complete Deployment Guide

This stack provides automated media management, downloading, and streaming services for homelab infrastructure. The configuration follows TRaSH-Guides.info best practices for optimal quality and automation.

These services were set up with lots of google-foo and TRaSH-Guides.info. This README was generated by Claude and manually revised for clarity and LLM-induced chaos.

## 🏗️ Architecture Overview

### Service Dependencies
```
Content Discovery (Overseerr) → Request Management → *arr Services
                                                          ↓
Indexer Management (Prowlarr) → Torrent/Usenet Sources → Download Clients
                                                          ↓
QBittorrent/SABnzbd → Downloaded Media → Plex Media Server
                           ↓
                   VPN (Gluetun) - Protects all download traffic
```

### Network Design Philosophy
- **VPN Kill Switch**: All download clients route through VPN with automatic kill switch
- **Dual Network Setup**: VPN network for download services, nginx network for external access
- **Privacy First**: Torrent and usenet traffic always encrypted and anonymized
- **Quality Automation**: TRaSH-Guides profiles for optimal media quality

## 🚀 Initial Setup

### Prerequisites
1. Docker and Docker Compose installed
2. VPN subscription (NordVPN configured in this example)
3. Usenet provider and indexers (optional but recommended)
4. Large storage volume for media (RAID recommended)
5. External nginx_network already created (from network stack)

### Directory Structure Setup

1. **Create project directory**:

In most setups, this path is wherever you want. If you clone this step is already completed. 

(Untested, but expected) In Unraid, this directory will need to reside in `/mnt/user/appdata/` as that is where app storage files go per [Unraid's documentation](https://docs.unraid.net/unraid-os/using-unraid-to/run-docker-containers/managing-and-customizing-containers/).

   ```bash
   mkdir media-services
   cd media-services
   ```

2. **Create directory structure**:
   ```bash
   mkdir -p {plex/{database,transcode/temp},gluetun,qbittorrent/{config,torrent_files},prowlarr,radarr,sonarr,lidarr,overseerr,bazarr,sabnzbd,recyclarr}
   ```

3. **Create data directory structure** (adjust paths to your storage):
   ```bash
   mkdir -p /path/to/your/storage/servarr_data/{torrents/{movies,tv,music},usenet/{movies,tv,music},media/{movies,tv,music}}
   ```

4. **Set permissions**:
   ```bash
   sudo chown -R 1000:1000 ./plex ./gluetun ./qbittorrent ./prowlarr ./radarr ./sonarr ./lidarr ./overseerr ./bazarr ./sabnzbd ./recyclarr
   ```

### Environment Configuration

Create `.env` file with your specific values. These keep sensitive variables like passwords out of your `docker-compose.yml` and in a separate file that `docker-compose.yml` can reference as a `${VARIABLE}`. Note the APPDATA_DIR and MEDIADATA_DIR environment variables. These is the relative path to persistent storage (app config data and media data, respectively). Depending on your OS environment, you'll need to pick one. Or customize it to your needs.

```bash
# User and timezone settings
LOCAL_USER=1000
TZ=America/New_York
APPDATA_DIR=. # This for most OS setups, excluding Unraid
# APPDATA_DIR=/mnt/user/appdata/media-services # This is for Unraid setups
MEDIADATA_DIR=../../RAIDdir # Customize this for where your media storage lives. For example, this maps to a RAID array
# MEDIADATA_DIR= # TODO: Identify the mapping to the Unraid disk array

# Plex Configuration
PLEX_CLAIM=claim-xxxxxxxxxx  # Get from plex.tv/claim
ADVERTISED_IPS=http://192.168.X.X:32400/  # Your server's LAN IP
LAN_SUBNET=192.168.X.0/24

# VPN Configuration (NordVPN example)
Nord_PRIVATEKEY2025=your_nordvpn_private_key
P2P_SERVERS=us9999.nordvpn.com  # P2P-enabled server

# HTTP Proxy for cross-network communication
HTTPPROXY_USERL=proxyuser
HTTPPROXY_PASSWORD=securepassword

# Static IP Addresses on VPN Network
PROWLARR_STATIC_IP=172.19.0.10
RADARR_STATIC_IP=172.19.0.11
SONARR_STATIC_IP=172.19.0.12
LIDARR_STATIC_IP=172.19.0.13
OVERSEERR_STATIC_IP=172.19.0.14
BAZARR_STATIC_IP=172.19.0.15
```

**Critical Environment Variables Explained**:
- `PLEX_CLAIM`: Token from plex.tv/claim to link server to your account (expires in 4 minutes)
- `P2P_SERVERS`: Must be P2P-enabled NordVPN servers for torrent traffic
- `HTTPPROXY_*`: Allows Prowlarr to communicate with QBittorrent across different networks

## 📋 Service Configuration and Deployment

Deploy services in this specific order to ensure proper dependencies:

### 1. Gluetun VPN

**Function**: VPN kill switch for all download traffic

**Prerequisites**: VPN subscription with WireGuard support

#### Docker Compose Configuration
```yaml
vpn:
  image: qmcgaw/gluetun
  container_name: gluetun
  networks: 
    - vpn
  cap_add:
    - NET_ADMIN
  devices:
    - /dev/net/tun:/dev/net/tun
  ports:
    - 8080:8080  # QBittorrent web port
    - 6881:6881  # QBittorrent
    - 6881:6881/udp
    - 8085:8085  # SABnzbd
  volumes:
    - ${APPDATA_DIR}/gluetun:/gluetun
  environment:
    VPN_SERVICE_PROVIDER: nordvpn
    VPN_TYPE: wireguard
    WIREGUARD_PRIVATE_KEY: ${Nord_PRIVATEKEY2025}
    SERVER_COUNTRIES: United States
    SERVER_HOSTNAMES: ${P2P_SERVERS}
    HTTPPROXY: on
    HTTPPROXY_LISTENING_ADDRESS: :8118
    HTTPPROXY_USERL: ${HTTPPROXY_USERL}
    HTTPPROXY_PASSWORD: ${HTTPPROXY_PASSWORD}
    HTTPPROXY_STEALTH: on
```

**Key Parameters**:
- `network_mode: service:vpn`: Other containers use this VPN connection
- `HTTPPROXY`: Enables proxy for cross-network communication
- `SERVER_HOSTNAMES`: Must use P2P-enabled servers

#### Deployment
```bash
docker compose up -d vpn
```

#### Post-Deployment Configuration
Verify VPN connection:
```bash
# Check VPN status
docker logs gluetun

# Verify external IP (should show VPN server IP)
docker exec gluetun wget -qO- ifconfig.me
```

#### Troubleshooting
**Issue**: VPN connection fails
```bash
# Check logs for authentication errors
docker logs gluetun | grep -i error

# Verify WireGuard key format
echo ${Nord_PRIVATEKEY2025} | wc -c  # Should be 44 characters

# Test with different server
# Update P2P_SERVERS in .env and restart
```

**Reference**: [Gluetun Documentation](https://github.com/qdm12/gluetun-wiki)

### 2. QBittorrent

**Function**: Torrent download client with VPN kill switch

**Prerequisites**: Gluetun VPN must be running

#### Docker Compose Configuration
```yaml
qbittorrent:
  image: lscr.io/linuxserver/qbittorrent
  container_name: qbittorrent
  network_mode: service:vpn  # Kill switch - no network without VPN
  environment: 
    PUID: ${LOCAL_USER}
    PGID: ${LOCAL_USER}
    TZ: ${TZ}
    WEBUI_PORT: 8080
  volumes:
    - ${APPDATA_DIR}/qbittorrent/config:/config
    - ${APPDATA_DIR}/qbittorrent/torrent_files:/torrent_files/
    - ${MEDIADATA_DIR}/servarr_data/torrents:/data/torrents/
  depends_on:
    - vpn
```

**Key Parameters**:
- `network_mode: service:vpn`: Ensures all traffic goes through VPN
- Volume mapping follows TRaSH-Guides structure

#### Deployment
```bash
docker compose up -d qbittorrent
```

#### Post-Deployment Configuration

1. **Access QBittorrent WebUI**: `http://your-server-ip:8080`

2. **Get default credentials**:
   ```bash
   # Username is always 'admin'
   # Get temporary password from logs
   docker logs qbittorrent | grep "password"
   ```

3. **Configure QBittorrent settings**:

  Follow the configuration instructions at [Trash-Guides.info](https://trash-guides.info/Downloaders/qBittorrent/Basic-Setup/) for setting QBittorrent correctly. Update username and password in the `QBittorrent > Tools > Options > WebUI` settings, as desired.

4. **Configure Categories** (for *arr integration):

  In the main WebUI, the left panel has a section called `Categories`. Right click in it and select `Add Category`.
   - Create categories: `movies`, `tv`, `music`
   - Set save paths:
     - `movies`: `/data/torrents/movies`
     - `tv`: `/data/torrents/tv`
     - `music`: `/data/torrents/music`

#### Troubleshooting
**Issue**: Can't access WebUI
```bash
# Check VPN is running first
docker logs gluetun | grep "You are running"

# Check QBittorrent logs
docker logs qbittorrent

# Verify port mapping through VPN
docker exec gluetun netstat -tlnp | grep 8080
```

**Issue**: Downloads not starting
```bash
# Verify VPN external IP
docker exec gluetun wget -qO- ifconfig.me

# Check QBittorrent can reach trackers
docker exec qbittorrent nslookup tracker.example.com
```

### 4. Prowlarr (Indexer Management)

**Function**: Centralized indexer management for all *arr services. Prowlarr is where you tell the downloader apps (QBittorrent and SABnzbd) where to look for downloads. Manage these indexes in Prowlarr versus across multiple *arr apps like Sonarr and Radarr.

**Prerequisites**: Download clients configured

#### Docker Compose Configuration
```yaml
prowlarr:
  image: lscr.io/linuxserver/prowlarr:latest
  container_name: prowlarr
  hostname: prowlarr-docker
  networks:
    vpn:
      ipv4_address: ${PROWLARR_STATIC_IP}
  environment:
    PUID: ${LOCAL_USER}
    PGID: ${LOCAL_USER}
    TZ: ${TZ}
  volumes:
    - ${APPDATA_DIR}/prowlarr:/config
  restart: unless-stopped
  ports:
    - 9696:9696
  depends_on:
    - vpn
    - qbittorrent
```

Note that Prowlarr is configured on the same Docker network as the VPN, but it does not access the internet through the VPN (i.e. `network_mode` is not set to `service:vpn` like Qbittorrent is). This is per warnings from [Trash-Guides.info](https://trash-guides.info/Prowlarr/prowlarr-setup-proxy/).

#### Deployment
```bash
docker compose up -d prowlarr
```

#### Post-Deployment Configuration

1. **Access Prowlarr WebUI**: `http://your-server-ip:9696`

2. **Configure Download Clients**:
   - **Settings → Download Clients**
    It is not necessary to configure the Qbittorrent and SABnzbd download client in Prowlarr. In this configuration, Prowlarr is only used as an index manager and not for content searches. The download clients will be configured in Radarr and Sonarr.
<!--

   - Username: `admin`

   - Category: Leave blank (Prowlarr will set per *arr service)
   - ✅ Test connection

   **SABnzbd Setup**:

   - Host: `gluetun`
   - Port: `8085`
   - API Key: (from SABnzbd config)
   - Category: Leave blank
   - ✅ Test connection -->
3. **Configure Download Clients**:
   - **Settings → Indexers**
   Set up the prixoy per the [Trash-Guides.info privoxy setup page](https://trash-guides.info/Prowlarr/prowlarr-setup-proxy/). This is useful for some indexers. Instead of running the entire container through the VPN, you only route specific indexers through the VPN via the privoxy.
   
   The gluetun image already has the proxy configured with the `HTTPPROXY_*` environment variables. Use those parameters when configuring the privoxy in Prowlarr.

4. **Add Indexer Proxy**:

   - **Settings → Download Clients → Add (+)**
   
   **QBittorrent**:
   - Name: `QBittorrent`
   - Host: `gluetun` (which is the VPN `container_name`) or the Docker Network IP of the VPN service (gluetun works for me here)
   - Port: `8080`
   - Category: `movies`
   - ✅ Test connection

   **SABnzbd**:
   - Name: `SABnzbd` 
   - Host: `gluetun` or the Docker Network IP of the VPN service (gluetun does NOT work for me here)
   - Port: `8085`
   - Category: `movies`
   - ✅ Test connection

4. **Configure Root Folders**:
   - **Settings → Media Management → Root Folders**
   - Add: `/data/media/movies`

5. **Configure Quality Profiles**:

   We'll be using TRaSh-Guides' quality profiles but instead of manually configuring them here, we'll use Recyclarr to keep them up to date and synced across *arr apps.

   <!-- - **Settings → Profiles → Quality Profiles**
   - Follow TRaSH-Guides for optimal quality settings
   - Create profiles: `Ultra-HD`, `HD-1080p`, `HD-720p` -->

6. **Add to Prowlarr**:
   - In Prowlarr: **Settings → Apps → Add (+)**
   - Application: `Radarr`
   - Prowlarr Server: `http://172.XX.0.10:9696` (Prowlarr's static IP) or `http://prowlarr:9696` (Prowlarr's address using its container name)
   http://prowlarr:9696
   - Radarr Server: `http://172.XX.0.11:7878` (Radarr's static IP) or `http://radarr:7878` (Radarr's address using its container name)
   - API Key: From Radarr **Settings → General**
   - ✅ Test and Save

## 🌐 Network Configuration Deep Dive

### Dual Network Architecture

**VPN Network (`172.XX.0.0/16`)**:
- All download-related services run through the VPN
- Provides kill switch functionality such that if the VPN is down, the download services cannot connect to the internet
- Static IPs for reliable communication

**Nginx Network (External)**:
- Plex and Overseerr have external access
- Connects to reverse proxy stack
- Enables remote streaming and media requests

### Service Communication Flow

```
Internet → VPN → Download Clients → Storage
    ↓
*arr Services → API Communication → Download Management
    ↓
Processed Media → Plex → External Streaming
```
